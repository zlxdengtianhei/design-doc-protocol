# Clean Context

Apply this when creating a new role. Define the result it must produce and name who will use that result. A role already doing a small task does not need a new session for cleanliness alone.

Give the new role five things:

1. **Task and role:** the original goal, latest effective correction, responsibility and choices already settled. Identify inference as inference.
2. **Necessary input:** exact source documents and versions, relevant sections and why each is needed. Give enough facts to work; fresh does not mean empty.
3. **Protected property:** state any independence, unseen-answer measurement or no-background readability requirement. Say what information would defeat it.
4. **Context and carrier:** default to a fresh session with selected facts. Check the host's actual history injection, workspace, skills, memory, tools, permissions and delegation ability. Carry prior facts in a curated packet; continue a prior session only when its interaction trace is indispensable.
5. **Output and consumer:** allowed writes, evidence, format, named recipient and the recipient's next decision.

Review the actual prompt and injected context before treating a role as independent. Model names or a label such as “fresh” cannot prove isolation. If an agent reads an unrelated file, stop that expansion, disclose it and continue useful work. If it sees an answer or author process that breaks a protected judgment, record the affected input and output, then have a clean role redo that judgment. Do not discard unrelated work solely because some other scope was exposed.

This skill describes the task packet and leakage response. The host owns dispatch, permissions, records and publication. Its concepts are adapted for this product from the author's Clean Context practice; this file is an independent, limited statement and carries no dependency on a private repository.
